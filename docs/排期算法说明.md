# 排期算法说明

> 发布任务的「计算模式 + 间隔」自动算出每条视频的发布时间。
>
> 涉及代码：`backend/app/services/publish_schedule.py` 的 `build_schedule` / `_schedule_fixed` / `_schedule_for_account_balanced`。

---

## 一、做什么

把"账号 A/B + 项目甲乙 + 每天上限 N 条 + 早上 7 点到晚 10 点 + 选哪种计算模式"自动算成一张张具体的发布明细：

| 序号 | 几号几点 | 项目 | 门店 | 简介 | 哪个账号 |
|---|---|---|---|---|---|
| 1 | 09-22 07:00 | 甲 | 朝阳店 | xxx | A |
| 2 | 09-22 07:10 | 乙 | 西单店 | yyy | B |
| ... | ... | ... | ... | ... | ... |

---

## 二、两种计算模式对比

| 维度 | fixed（固定间隔） | balanced（均衡间隔） |
|---|---|---|
| 用户输入 | 固定间隔（分钟）| 均衡步长（分钟）|
| 节奏感 | 流水线，每隔固定时间出一件 | N 项目轮转，每轮隔段再开始 |
| 项目条数对称 | 可能差 1 条 | 完全对称 |
| 适合场景 | 项目少（1-3）、节奏密集 | 项目多（4+）、希望均匀分配 |
| 末条可能少 1 条 | 是 | 否 |

---

## 三、fixed（固定间隔）算法

**核心规则**：每账号独立 seq；步长 = `max(fixed_min // n_proj, 10)`。

```
每条 plan_time = start_time + seq × fixed_interval_min
project_idx = seq mod n_proj
每账号独立 seq=0..acc_limit-1
末条约束：t ≤ end_time − step（step 为项目间步长）
```

**例子**：fixed=10, n_proj=3, accounts=2, 每账号 4 条

| 账号 | seq | 项目 | 时间 |
|---|---|---|---|
| 0 | 0 | 项目0 | 07:00 |
| 0 | 1 | 项目1 | 07:10 |
| 0 | 2 | 项目2 | 07:20 |
| 0 | 3 | 项目0 | 07:30 |
| 1 | 0 | 项目0 | 07:00 |
| 1 | 1 | 项目1 | 07:10 |
| ... | ... | ... | ... |

**末条不对称**：末条所在项目可能比前项目少 1 条（seq 推进式截断）。

---

## 四、balanced（均衡间隔）算法

**核心规则**：项目轮流上流水线，每轮隔「均衡间隔」再开始下一轮。

```
步长 = max(均衡间隔 ÷ 项目数, 10)  # 步长下限 10min
第 N 条项目 = N mod n_proj
第 N 条组号 = N // n_proj
第 N 条时间 = 组号 × 均衡间隔 + (N mod n_proj) × 步长
```

**例子**：均衡 60, n_proj=3, 步长 20

| 第几条 | 项目 | 时间 |
|---|---|---|
| 1 | 项目0 | 07:00 |
| 2 | 项目1 | 07:20 |
| 3 | 项目2 | 07:40 |
| 4 | 项目0 | 08:00 |
| ... | ... | ... |

---

## 五、末条约束（两种模式都有）

```
最后一条 ≤ 结束时间 − 步长
```

末条所在项目可能比前项目少 1 条（fixed 模式），需要对称请用 balanced。

---

## 六、步长下限 10 分钟

**为什么 ≥ 10 分钟**：平台风控拦截频率过高的发布。

| 配置 | 算出步长 | 实际步长 | 警告 |
|---|---|---|---|
| fixed 60 + 8 项目 | 7 | 10 | ⚠️ 提示减少项目 |
| fixed 120 + 8 项目 | 15 | 15 | 无 |
| fixed 40 + 2 项目 | 20 | 20 | 无 |

---

## 七、同账号冲突重排（仅 balanced）

当「步长 × 项目数 > 均衡间隔」时，seq 翻页时 t 可能倒回，导致同账号同时间发两条。系统自动按步长推到下一个空 slot（不同账号仍可同时间）。

---

## 八、视频简介为空

视频简介为空也能正常排期。系统自动用「空简介」占位，简介 ID 留空。

---

## 九、时间窗口校验

| 错误场景 | 系统反应 |
|---|---|
| 结束时间 ≤ 开始时间 | 报错「结束时间必须晚于起始时间」 |
| 跨天（22:00 → 次日 02:00） | 报错「时间窗必须同日」 |
| 时间窗排不下指定数量 | 自动截断（不报错） |
| 账号列表为空 | 报错「账号列表不能为空」 |
| 项目列表为空 | 报错「项目列表不能为空」 |
| 间隔 ≤ 0 | 报错「间隔必须 ≥ 1 分钟」 |
| 时间格式错误 | 报错「时间格式无法解析」 |

---

## 十、多账号怎么排

**每个账号独立排期**：账号 A 排 5 条 + 账号 B 排 5 条 = 共 10 条。不同账号可以同时发。

- **global 模式**：所有账号共享一个上限值
- **per_account 模式**：每个账号各自的上限

---

## 十一、上限模式的两种用法

### 全局上限（global）

每个账号都按 global 限计算。例：2 账号 + global 75 = 共 150 条。

### 分账号上限（per_account）

每个账号按各自 limit。例：账号 A=5 + 账号 B=8 = 13 条。

---

## 十二、异常层次

| 异常类 | category | 触发场景 |
|---|---|---|
| `ScheduleOverflowError` | time | 排期溢出基类（默认） |
| `ScheduleTimeShortageError` | time | 时间窗不足 |
| `ScheduleVideoShortageError` | video | 视频目录视频数不足 |

前端按 `category` 区分错误类型：
- `time`：回到 step 5（视频数量/排期区间）调整
- `video`：回到 step 2（视频目录模式）调整源视频

---

## 十三、视频目录模式（独立排期）

`VideoDirScheduleConfig` / `build_video_dir_schedule`：每个目录视为虚拟项目，按扫描顺序顺排视频文件。`manual_intros` 字典按目录 ID 索引该目录的简介列表。

字段命名与 `ScheduleConfig` 一致（`schedule_mode` / `fixed_interval_min` / `balanced_step_min`），便于上层 service 统一构造。

---

## 十四、配置建议

| 场景 | 推荐模式 |
|---|---|
| 项目数量少（1-3），节奏密集 | fixed |
| 项目数量多（4+），希望均匀分配 | balanced |
| 视频简介大部分为空 | 任意模式（空简介自动占位） |
| 多账号并行发 | 任意模式（账号独立） |
| 需要项目条数完全对称 | balanced |
| 希望节奏完全均匀 | fixed |

---

## 十五、常见疑问

**Q：为什么 fixed 模式最后一个项目少 1 条？**

A：seq 推进式截断。末条时间超过「结束时间 − 步长」时停。需要对称请用 balanced 模式。

**Q：项目数太多会怎样？**

A：步长自动提到 10 分钟（带警告）。时间窗排不下时自动截断。

**Q：排期时间表预览在哪里？**

A：发布向导 step 5 → step 6「预览排期」按账号分组展示时间表。

**Q：确认后能改吗？**

A：不能。确认后任务进入 running，明细锁定。如需调整先取消再新建。

**Q：fixed 和 balanced 哪个更安全？**

A：balanced 项目分布均匀，更适合多项目场景。fixed 节奏感强，适合单一项目高频发布。

**Q：项目数少但用 balanced 模式可以吗？**

A：可以。1 个项目 + balanced 60 = 步长 60 → 每条相隔 60 分钟。

**Q：两个账号同一时间发会冲突吗？**

A：不会。不同账号的发布动作独立并行。

**Q：末条约束会减少条数吗？**

A：会自动截断，不抛错。例如 limit=100 但时间窗只能排 23 条 → 实际 23 条。

---

## 十六、边界场景速查

| 场景 | 系统行为 |
|---|---|
| `interval < 1` | 报错（间隔必须 ≥ 1 分钟）|
| 窗口 < 间隔（balanced）| 报错「连 1 条都排不下」 |
| `projects=()` | 报错「项目列表不能为空」|
| 所有项目 intros=() | 仍正常排期，占位条目 |
| `interval // n_proj < 10` | 静默提升到 10 + 警告 |
| 同账号同时间（balanced）| 按 step 推到空 slot |
| `n_proj × step > interval` | 触发冲突重排 + 警告 |
| 跨日窗口 | 报错「时间窗必须同日」|
| 空账号 | 报错「账号列表不能为空」|
| 限制不足 | 自动截断（不抛错）|
| 多账号同时 | 各账号独立排期，可同时发 |
