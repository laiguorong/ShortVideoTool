# 视频组合算法约束定义

> 实现位置：`backend/app/services/creation_service.py` 的 `_pick_combinations` 与 `generatable_count`。
>
> 算法核心：接受-拒绝采样 + 4 项约束，按权重挑选分镜片段组合。

---

## 约束 1：同源率 ≤ 50%

**定义**

- 同一批添加的视频分割出的片段共享 `source_index`
- 组合内出现次数最多的 `source_index` 占比 > 50% → 拒

**举例**（3 分镜）：

| 组合 | 同源最多 | 占比 | 结果 |
|---|---|---|---|
| [A-1, A-2, B-1] | 2 | 67% | 拒 |
| [A-1, B-1, C-1] | 1 | 33% | 通过 |

---

## 约束 2：位置重叠 ≤ 50%（与历史比对）

**定义**

- 拿当前组合与历史**每条**已生成视频对比
- 相同片段数 ÷ 分镜数 > 50% → 拒
- 扩容场景（项目分镜数 K→N）：用新视频前 K 段与历史比重叠率除以 N

**举例**（3 分镜，历史 [旧A, 旧E, 旧I]）：

| 当前 | 撞 | 占比 | 结果 |
|---|---|---|---|
| [旧A, 旧E, 旧I] | 3 | 100% | 拒 |
| [旧A, 新1, 旧I] | 2 | 67% | 拒 |
| [旧B, 新1, 旧J] | 0 | 0% | 通过 |

---

## 约束 3：按权重采样（使用次数越少越优先）

**定义**

- 权重公式：`weight = max(0, 10000 - used_count)`
- 每轮每个分镜按权重选 1 个片段；选中后 `used_count += 1`
- 全部 10000 起步，新片段天然排最前

**举例**（分镜 1 有 3 片段）：

| 片段 | used_count | 权重 |
|---|---|---|
| A | 5 | 9995 |
| B | 2 | 9998 |
| C | 0 | 10000 |

排序：C > B > A。

---

## 约束 4：同权重随机选择

**定义**

- 同分镜下权重相同的多个片段：`random.choice()` 均匀随机选
- 不按 ID 顺序，保证分布均匀

---

## 算法整体流程（接受-拒绝采样）

```
while 选中数 < 目标数 and 连续失败 < count × 20 + 100:
    每分镜按权重采样一个片段（约束 3+4）
    if 重复 combination_key: 重抽
    if 约束 1 不通过: 重抽
    if 约束 2 不通过: 重抽
    选中 → used_count += 1
```

- 取消信号：`TaskInfo.cancel_requested=True` → 立即退出
- 耗尽保护：连续失败超阈值 → 退出，状态栏提示"组合耗尽"
- 数据库层硬约束：`generated_video.combination_key` 唯一索引兜底

---

## 组合可生成数（`generatable_count`）

理论可生成数由倒推算法算得（`_uniform_count`）：

| 分镜数 n | 候选 c | 可生成数 V(n, c) |
|---|---|---|
| n ≤ 2 | c | c |
| n = 3 | c | c² − 1 |
| n = 4 | c | c(c²−1) / 3 |
| n = 5 | c | 2·V(4) + 1 |
| n ≥ 6 | c | 锚点优先 + V(k)=V(k−1)+V(k−2) 外推 |

**业务口径**：当各分镜候选数不均时，可生成数取 `floor(m × V(n, C) / C)`（m 为最小、C 为最大候选数）。

`project.legal_total` 缓存该值；加/删分镜/片段接口末尾自动刷新。
